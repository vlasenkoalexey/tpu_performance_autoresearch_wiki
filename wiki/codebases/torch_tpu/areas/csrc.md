# Area: `csrc`

## Purpose
`csrc/` is the C++ core that makes PyTorch run on TPU. Every ATen op registered for the `PrivateUse1` (`tpu`) device enters here: a kernel written with the `TT_KERNEL` macro family ([aten-kernel-authoring](../concepts/aten-kernel-authoring.md)) builds a parameter cache key and an op-name context, then hands a StableHLO builder to the eager dispatcher ([eager-op-dispatch](../concepts/eager-op-dispatch.md)). The dispatcher does not run anything immediately; it records a deferred node over device buffer references ([deferred-execution-and-materialization](../concepts/deferred-execution-and-materialization.md)). How many ops accumulate before a graph is cut is decided by the eager mode held in the thread-local context-state stack ([context-states-and-execution-modes](../concepts/context-states-and-execution-modes.md)).

When something forces a materialization (a host copy, `.item()`, a sync, a collective, or the repeated-op-sequence heuristic in fused mode), the pending graph is traversed, keyed and compiled. The compile path ([compilation-pipeline](../concepts/compilation-pipeline.md)) builds an MLIR module, runs torch_tpu's own MLIR passes ([mlir-optimization-passes](../concepts/mlir-optimization-passes.md)) and hands it to XLA through PjRt ([pjrt-client](../concepts/pjrt-client.md)); the result is memoized in the multi-tier cache ([compilation-cache](../concepts/compilation-cache.md)) under a key whose composition decides when you recompile ([compilation-cache-key](../concepts/compilation-cache-key.md)). The torch.compile path reuses the same machinery: [compiled-mode](../concepts/compiled-mode.md) replays an FX graph on placeholder tensors to build the same deferred graph and compiles it once.

The area also owns the performance-critical kernels and collectives that are not plain StableHLO: the Mosaic flash-attention kernels behind SDPA ([scaled-dot-product-attention](../concepts/scaled-dot-product-attention.md)), the Mosaic matmul builders ([mosaic-matmul](../concepts/mosaic-matmul.md)) and the experimental KILN kernel DSL ([kiln-kernel-dsl](../concepts/kiln-kernel-dsl.md)), fused optimizers ([fused-optimizer-kernels](../concepts/fused-optimizer-kernels.md)), the c10d process group that turns collectives into graph ops ([process-group-and-collectives](../concepts/process-group-and-collectives.md)), and ragged all-to-all / SparseCore ops for MoE and embeddings ([ragged-collectives-and-sparse-ops](../concepts/ragged-collectives-and-sparse-ops.md)).

## How the units connect
- **Dispatch -> defer -> materialize -> compile -> execute** is the spine. [eager-op-dispatch](../concepts/eager-op-dispatch.md) records nodes; [deferred-execution-and-materialization](../concepts/deferred-execution-and-materialization.md) and [tensor-synchronization](../concepts/tensor-synchronization.md) decide when a graph is cut and run; [compilation-pipeline](../concepts/compilation-pipeline.md), [compilation-cache](../concepts/compilation-cache.md) and [compilation-cache-key](../concepts/compilation-cache-key.md) turn a graph into a cached executable; [pjrt-client](../concepts/pjrt-client.md) runs it.
- **Op lowering helpers** shared by every kernel: [stablehlo-op-builder](../concepts/stablehlo-op-builder.md) (MLIR constants, broadcasting, result plumbing), [dtype-and-precision](../concepts/dtype-and-precision.md) (dtype mapping, matmul precision, excess precision), [view-decomposition](../concepts/view-decomposition.md) (strided views without pointer aliasing), [reductions](../concepts/reductions.md), [dynamic-shape-ops](../concepts/dynamic-shape-ops.md) (bounded dynamism), and the cross-cutting [error-handling](../concepts/error-handling.md) and [op-names-and-python-context](../concepts/op-names-and-python-context.md) layers that every `TT_KERNEL` wraps around.
- **Data movement**: [host-device-copy](../concepts/host-device-copy.md) is the one direction that forces a sync (TPU -> CPU); [batch-host-device-transfer](../concepts/batch-host-device-transfer.md) (`csrc/experimental`) batches many buffers per wait and hosts the precompiled nonzero Mosaic kernel; [device-streams-generators-and-rng](../concepts/device-streams-generators-and-rng.md) owns per-stream queues and the device RNG state.
- **Small units without their own page**: `csrc/api` (a stable `TensorBufferHandle` for external callers), `csrc/internal/dynamism` (pad/slice modules behind bounded dynamism), and the per-op kernel directories under `csrc/ops/` (pooling, linalg, convolution, norms, losses, embedding, ...) are catalog-only; each follows the [aten-kernel-authoring](../concepts/aten-kernel-authoring.md) pattern.
