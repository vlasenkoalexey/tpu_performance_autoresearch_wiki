# Environment variable reference, grouped by subsystem (with readers)

## Definition
The project's env-var reference lists the user-facing knobs of vllm-torchtpu in six
groups: platform/runtime/compile cache, parallelism and scheduling, MoE and
quantization, attention and KV-cache layout, disaggregated serving (Raiden), and
profiling/debugging. This page reproduces those groups through the TPU-performance
lens and, for every knob, links (a) its declaration in the `envs.py` registry and
(b) the function(s) that actually read it at commit `bf318e424`, with the code's real
default and accepted values. Where the doc and the code disagree, the code value is
given and the disagreement is flagged. The registry mechanics themselves (lazy
lookup, parsing, compile-cache-key participation) are on
[env-var-registry-and-compile-key](env-var-registry-and-compile-key.md).

The doc covers ~70 of the ~185 entries in the registry; the rest (kernel tile sizes,
per-model admission switches, Raiden internals) are only documented by comments in
[`envs`](../catalog/src/vllm_torchtpu/envs.md).

## In vllm-torchtpu (grounded)
Column "Default" is the value in `envs.py` at this commit. "Key?" says whether the knob
joins the compile cache key (every registry entry does unless listed in
[`_TPU_COMPILE_ENV_IGNORED`](../catalog/src/vllm_torchtpu/compilation/tpu_compiler.md#_TPU_COMPILE_ENV_IGNORED);
changing a "yes" knob forces a recompile on the next start).

## Why it matters / when it applies
- These knobs are the TPU plugin's equivalent of backend selection flags: many kernel
  and layout choices (SparseCore MoE, fused EP MoE, block-major KV, sparse MLA layout,
  W8A16 small-bucket matmul) are *only* reachable through env vars, not CLI flags.
- Most of them join the compile cache key, so an A/B on a "yes" knob always pays a cold
  compile (or needs a pre-warmed cache per arm). Orchestration knobs (ports, Raiden
  identity, precompile scheduling, PP handoff) are deliberately excluded.
- The six doc-vs-code mismatches flagged above (`VLLM_XLA_CACHE_PATH`,
  `TPU_TOKEN_BUCKET_LINEAR` semantics, `MOE_FUSED_EP_KERNEL_IMPL` values, sparse-MLA
  `tc`, `TPU_RAIDEN_RESHARD_IMPL=host`, `TPU_KV_RESHARD_TRANSPORT=tcp`) would either do
  nothing or raise `ValueError` at startup if copied verbatim from the doc.
