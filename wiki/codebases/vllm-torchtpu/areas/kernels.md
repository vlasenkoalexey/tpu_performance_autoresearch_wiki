# Area: `src/vllm_torchtpu/kernels`

## Purpose
`src/vllm_torchtpu/kernels` holds the JAX/Pallas kernels the plugin runs in place of XLA's default lowering wherever that lowering wastes HBM bandwidth, leaves a collective exposed, or recompiles per shape. Kernels in this area are plain JAX functions. They are not called by models directly. The [layer core](../concepts/attention-and-layer-core.md) wraps them in `shard_map` and the [custom-op adapters](../concepts/custom-ops.md) register them as opaque torch ops, so the compiled graph sees one stable op call per kernel. Most of this repo's TPU inference performance work is in this area.

The load-bearing units, each with its own page:
- **Attention.** [ragged-paged-attention-kernel](../concepts/ragged-paged-attention-kernel.md) is the default for standard models: mixed prefill and decode in one kernel, with the KV cache write fused in. [batched-ragged-paged-attention-kernel](../concepts/batched-ragged-paged-attention-kernel.md) is an experimental two-call successor with a scalar scheduler kernel. [mla-attention-kernels](../concepts/mla-attention-kernels.md) covers dense, sparse and masked-dense MLA. [pcp-streaming-rpa-kernel](../concepts/pcp-streaming-rpa-kernel.md) rings KV pages across prefill-context-parallel ranks.
- **MoE.** [fused-moe-kernels](../concepts/fused-moe-kernels.md) computes the expert half of an expert-parallel MoE layer in one SPMD kernel that pushes result rows to their owners, so no combine reduce-scatter is needed. [adaptive-fused-moe-kernel](../concepts/adaptive-fused-moe-kernel.md) is a fork with separate W1/W2 weight rings. [sparsecore-ragged-gather-scatter](../concepts/sparsecore-ragged-gather-scatter.md) moves the dispatch/combine data on SparseCore.
- **Recurrent and model-specific.** [gated-deltanet-kernels](../concepts/gated-deltanet-kernels.md) and [gdn-pcp-fused-kernel](../concepts/gdn-pcp-fused-kernel.md) cover hybrid linear-attention layers. [deepseek-v4-compress-and-store-kernel](../concepts/deepseek-v4-compress-and-store-kernel.md) and [deepseek-v4-streamindex-topk-kernel](../concepts/deepseek-v4-streamindex-topk-kernel.md) cover DeepSeek-V4's compressor and sparse indexer. [kimi-k3-kernels](../concepts/kimi-k3-kernels.md) has the K3 ring collectives and KDA kernels.

Smaller units without a page of their own supply grouped matmul, quantized matmul, flash attention for vision and diffusion towers, decode-specialized MoE experiments, and pool utilities. Their roles are listed below.

## How the units connect
The kernels share a few building blocks. Most MoE paths end in the megablox grouped matmul, many kernels read the same paged KV pool through the same typed-view helpers, and model-specific kernels reuse the generic attention structure. Units without a page:

- **`megablox`**: `gmm_v2`, the grouped (ragged) matmul behind the GMM MoE path in [layers](layers.md) (`layers/core/fused_moe_gmm.py`), with fused gated activations, packed low-precision weights and tuned tile sizes. It is also the matmul core inside [fused-moe-kernels](../concepts/fused-moe-kernels.md) and [adaptive-fused-moe-kernel](../concepts/adaptive-fused-moe-kernel.md). `moe_onehot_unpermute.py` is a blockwise version of the one-hot combine.
- **`quantized_matmul`**: Pallas quantized matmul (per-channel and blockwise scales) with a tuned block-size table and a pure-JAX reference. Used by the linear-layer bridge in [quantization-methods](../concepts/quantization-methods.md) and by the TP decode MoE kernel.
- **`flash_attention`**: a non-paged flash attention with segment ids and a tuned-parameter table. `layers/core/attention_interface.py` wraps it for the vision-encoder attention adapter.
- **`diffusion_attention`**: a hand-written splash-style attention for diffusion transformers. A cost-model block-size autotuner reads VMEM size and MXU edge from the attached chip. There is also a fused q/k RMSNorm + interleaved RoPE kernel for Wan. Both are used by [omni-diffusion-support](../concepts/omni-diffusion-support.md).
- **`deepseek_v4/core_attention`**: the DSv4 attention kernels (MLA ragged paged attention, the sliding-window variant, sparse MLA over CSA top-k pages, and a SparseCore gather of the nope/rope caches). The DSv4 attention custom op calls them; see [deepseek-v4-model](../concepts/deepseek-v4-model.md).
- **`deepseek_v4`** (root): the CSA compressed-cache byte layout shared by the compressor, the attention kernels and the runner's DSv4 KV allocation; DSv4 RoPE variants fused with norm or quantization; the RoPE-fused `wo_a` output projection; and the exact SparseCore top-k that [deepseek-v4-streamindex-topk-kernel](../concepts/deepseek-v4-streamindex-topk-kernel.md) calls after scoring.
- **`deepseek_v4/mhc`**: Pallas kernels for DSv4's multi-stream residual mixing (`mhc_pre`, `mhc_post`, and the fused post+pre seam kernel that [deepseek-v4-model](../concepts/deepseek-v4-model.md) uses to merge each layer boundary into one pass).
- **`experimental/moe_tp_decode`**: one TP rank's whole decode MoE layer (router, routed and shared experts, and an in-kernel all-reduce over the TP mesh) in a single `pallas_call`, so no XLA all-reduce follows. `can_use_moe_tp_decode` is the trace-time admission check; the adapter in `layers/adapter/moe_tp_decode.py` calls it.
- **`experimental/fused_moe_decode`**: routed experts, shared expert and all-reduce in one call for MoE tensor parallelism at decode row counts. Each active expert's small weight slice is visited once instead of paying per-expert fixed cost in two GMM kernels plus permute/combine.
- **`experimental`** (root, `moe_dense_expert.py`): small-batch FP8 MoE without token permutation. Each non-empty local expert's weights are DMA'd once and outputs accumulate in FP32 VMEM. The GMM MoE path selects it through `can_use_dense_expert`.
- **`collectives`**: an all-gather matmul kernel with tuned block sizes and a neighbour barrier helper. Nothing under `src/` calls it at this commit.
- **`kernels`** (root): `pool_adapters.py` gives typed per-request gather/scatter and block copy over byte regions of the unified KV pool (used by the KDA and Mamba-state custom ops), on top of the Mosaic `ref.bitcast` views in `typed_ldst.py`. `router_topk.py` is a sort-free MoE router top-k (k max-and-mask passes instead of a full sort). `partial_kv_update.py` is an in-place slot scatter whose cost scales with the update size rather than the pool size (exercised only by tests at this commit).

See [kv-cache-layout-and-hbm-budget](../concepts/kv-cache-layout-and-hbm-budget.md) for the pool layouts these kernels read and write.
